Release notes

What changed in each version of Hearth OS, newest first, and what's planned next.

Hearth OS 1.11 · November 13, 2026 Latest

  • Hearth Link pairs once for all your devices: pairing asks My device or A friend's device. Your own devices swap their lists, so a new one is paired with every device you have, and removing one removes it everywhere; a friend's device stays paired only with the device it paired with, for copying games, and never sees the others or anything personal. A device on an older Hearth OS stays paired as now (docs/HEARTH-LINK.md, "Your devices and friends' devices") (needs testing on a device)
  • Server mode's new gold look, the Hearth AI Command Center's: the AIs on this PC as living cores, the same shapes, colours and talking motions as in the Command Center (AI chat's model, ComfyUI, Voices, Whisper, AI sharing), with who's being answered; everything the dashboard showed before, plus last-hour graphs on graphics memory, storage, power and network, graphics memory by app, Voices and Server apps tiles, the schedule's next switch, and a QR code to open the web page on your phone; the countdown, menu, details and idle screen in gold, with faint cores on the dimmed clock; Reduce motion keeps the cores still (needs testing on a device)
  • Hearth Recovery opens on a health check (the approved mockup B): it looks at the drive alone, offline and without changing anything (the drive's own self-check, free space, which versions started fine from the installed system's journal, a display setting on trial, the automatic fallback, your files) and says what's wrong, with one suggested fix front and centre (start the previous version, reset the display settings, Desktop Mode to free up space, or copy your files off a failing drive) and the other tools beside it; Y checks again; choosing a version shows how each one started lately. A portrait screen keeps the plain list. hearth-recovery health, tested with the Recovery screen test (needs testing on a device, and on a Recovery USB once it's rebuilt)
  • Fix: Voice Studio's Install stopped at once with "PyTorch didn't install … no such option: --progress-bar": pip's progress option was given before the install command, where pip doesn't accept it (needs testing on a device)
  • No more "… (classic)" in the app menu: the old Hearth Files, Terminal, Text Editor and Calculator keep their plain names (each desktop already shows one app of each kind), and an old "(classic)" is taken off (needs testing on a device)
  • A better app menu search, in every menu style: names that are or start with what you type first, then a word in the name, words in any order ("man task"), initials ("tm" → Task Manager), one typo ("calculater", "tsak"), accents and dashes ignored ("cafe", "wifi"), the program's own name, Windows' names (explorer, cmd, notepad, control panel, taskmgr, snip…), and apps you opened lately a little higher; the Best match is the top score of apps, games and Settings pages (needs testing on a device)
  • Apps for hardware a PC doesn't have are hidden: NVIDIA Settings only shows with an Nvidia graphics card. Worked out at every sign-in (a card put in shows it at once), nothing is uninstalled, and nothing waits on it (needs testing on a device)
  • The desktop shell's slow leak (1.5 GB and 100% CPU after 25 hours on 1.10, against about 440 MB): the helper calls Desktop, Files and file Properties make are always cleaned up, even when the window that asked closed meanwhile; the shell writes down its own memory and CPU every 10 minutes (in Send logs, "Desktop shell health"), and when it has grown far past normal or stays busy it refreshes itself, only while the screen is off or locked and none of its windows is open, then says so. The samples show what else still grows (needs testing on a device)
  • Memory and swap, on by default (the approved mockup): compressed memory (zram) sized for each PC (1.5× memory up to 8 GB, 1× up to 16 GB, half above; up to 2× with the recommended size marked), zstd or the other ways this kernel offers (lz4, lz4hc, deflate), swappiness 200 with zram, Keep memory free (Off, 2 GB by default, 25%, 50%) as the kernel's watermark, page-cluster 0, no watermark boost; your drive swap file (/var/swap/swapfile) used after zram, made or resized only when you press it, up to 64 GB and always leaving 20 GB free on C:. Task Manager › Performance › Memory › Swap & settings and Settings › System › Memory; Save, Try until restart and Back to recommended. Your test files (99-hearth-memory-test.conf, hearth-zram-test.service) keep working and their values are shown as yours; Use Hearth's settings hands them over with the same values (the files kept as .bak). Your own /etc/sysctl.d files win. Nothing waits for it at start-up (needs testing on a device)
  • When memory runs out (the memory guard, Off / Gentle / Strong): instead of the PC freezing, Hearth closes the one app using the most memory and swap, all of its processes, and tells you which; never one on your Never close list (the desktop, Steam, the game you're playing, the AI Command Center, and any you add), which the kernel's own last resort spares too. No MGLRU min_ttl (it closed the Command Center and Claude on the laptop) (needs testing on a device)
  • Memory "In use" counted the way Windows does (total − free − cache) in Task Manager, Resource Monitor and the stats overlay: it said 100% in use with gigabytes free when Keep memory free was high (needs testing on a device)
  • Task Manager, improved (the approved mockups): Processes with PID, Compressed (memory moved to zram or swap) and Power columns and a Hearth group; right-click End process tree, Set priority (Normal, Below normal, Low), Run on these cores, Limit CPU / memory (a cap on the app's own scope, never closed), Never close when memory runs out, Go to details; Details with Parent, Swapped, Threads and Priority, and Set priority / affinity; each Performance page opens a settings tab: CPU Power & settings (power mode, turbo boost, top speed, temperature, throttling), Disk Health & settings, Network (metered, a mobile hotspot), GPU Tuning (LACT), Battery Health & settings (health, cycles, a charge limit) — remembered in /etc/hearth/hardware.json and put back at every start (needs testing on a device)
  • Task Manager: Scheduled tasks (systemd timers: yours on / off, the system's read only, next and last run) and Users (who is signed in, their CPU, memory and processes) (needs testing on a device)
  • Task Manager › App history: processor time, disk read and written and when each app was last used, since a date, counted every 5 minutes by a small user timer (only ~/.local/state/hearth/app-history.json), with Delete usage history (needs testing on a device)
  • Task Manager › Performance › CPU › Game cores (off unless you turn it on): while a game runs it gets its own cores (2, 4 or 6 of 8, say) and the system's services (updates, AI, builds) run on the others; runtime-only, so a restart or turning it off shares every core again (needs testing on a device)
  • Resource Monitor: Disk tab (every drive's kind, file system, busy, response, free, total, how full and temperature; files the busiest programs have open, ✎ for writing), Network tab (each program's download and upload speed from its TCP connections, and each connection's ping), Graphics tab (3D, video decode and video memory per program; 3D, video decode, video memory and temperature graphs) (needs testing on a device)
  • Hearth Files, the rest of the approved mockups (files-6 to files-8): Extra large icons, View › Navigation pane, and the right-click's Pin to the left menu and Open in Terminal (tabs, the details pane, Copy as path and the quick icons on top were already there) (needs testing on a device)
  • Graphics card controls with LACT 0.10.1 (MIT) in the image: Task Manager › Performance › GPU › Tuning opens it, for fan curves, power limits and undervolting on Nvidia, AMD and Intel. Its daemon stays off until you open tuning the first time (one password prompt), so nothing about the card changes by itself (needs testing on a device)
  • Low battery: a warning at 10% and at 5%, and at 3% the PC is put away safely before the battery dies: hibernated where a hibernation has come back on that PC before, otherwise a clean shutdown at 2% (UPower), so no files are lost. Plugging in cancels (needs testing on a device)
  • A PC moved from the Fedora edition gets Hearth's own boot menu (sudo /usr/libexec/nimbus/hearth-boot-move run --yes, only when asked): it kept starting through Fedora's shim and GRUB, without Hearth's themed menu and ordering. A full copy of the EFI partition and the menu first, Fedora's loader kept with its own firmware entry ("Hearth OS (old boot menu)"), a menu both GRUBs read, then Debian's signed shim and GRUB; undo puts the copy back. Proven in a virtual PC: Fedora's loader starts, the move, then it starts through Debian's GRUB (needs testing on a device: the Nvidia PC)
  • Hearth Files, the Windows 11 left menu (the approved option A): a narrow 158 px menu you can drag wider or narrower (remembered); Home, Gallery, Home server (your devices' shares); your folders; This PC with Hearth (C:) open (Users, Program Files, Windows apps) and the other drives; Network; the Linux folders folded under "Linux" only with Show the Linux folders. Folders with thousands of files open much faster: each name is sorted with its keys worked out once, and the hidden view no longer builds rows (needs testing on a device)
  • Hearth's terminal speaks C:\: cd C:\Users, cd G:\Steam, cd.., dir (/a /s /w /b), copy, xcopy, robocopy, move, ren, del, rd (/s), md, type, cls, where, tasklist, taskkill, ipconfig, ver, start, explorer and notepad, with C:\ and the other drive letters understood; Linux commands and paths work as always; del, move and rd /s ask first; off with HEARTH_WINDOWS_COMMANDS=0; never in scripts (needs testing on a device)
  • Saved games (Settings › Gaming), with Ludusavi 0.31.0 (MIT) in the image: every game's saves found (Steam, Proton, Wine, Heroic, Lutris and thousands of others), backed up into your Saved Games folder and put back, all at once or one game at a time, on this PC or another after a reinstall; only when you press it (needs testing on a device)
  • One C: for Windows apps and Steam's Windows games: each keeps its own Windows setup, but its Documents, Desktop, Pictures, Music, Videos, Downloads and a new Saved Games folder are your real folders, and its drives get the same letters as in Hearth (Steam games at every sign-in, in the background). Only empty folders and Hearth's own links change, so saves already inside a game's setup stay exactly where they are (needs testing on a device)
  • A Compatibility section for Windows apps (Settings › Windows apps): Proton version, DXVK, VKD3D and the Windows version together with "Use these files from Windows" (DLL overrides like d3d9 or dinput8, the app's own copy first) and the common fixes (no esync, no fsync, more memory for old 32-bit games, Nvidia DLSS, hide an Nvidia card, old OpenGL games), all remembered per app (needs testing on a device)
  • Hearth (C:) everywhere, step 1 (the approved mockups cdrive-1 … 4): every app's Open and Save window (Hearth's picker, which apps from apt and Flatpak use too) shows Hearth (C:) and its Windows folder names, accepts a typed C:\\ or G:\\ path, and always hands the app the real path (a folder that's only a name in the view can't be saved into); Properties shows where a file is as C:\\Users\\… with the Linux path under it, and Copy gives the C:\\ form; Settings › Drives & folders: Show system folders, Apps you install, Terminal speaks C:\\ (on / off). The Run box already took C:\\ paths. Nothing on disk moves (needs testing on a device)
  • One Settings › Your devices page: your paired devices at the top (Hearth Link), and on the PC that's the home server a "This PC is the home server" section under them saying what it does (shared folders, backups, people, AI, what's paused while you play), one press to its pages. Hearth Link and the home server stay two services underneath, and every setting stays where it's saved (needs testing on a device)
  • Proton detector for Hearth Games: when Hearth picked the Proton (your own pick always wins), the game is watched; if it closes right away with an error, that Proton is noted and the next one is tried first next time (a notification says which), and one it ran well with is remembered for that game (needs testing on a device)
  • Resource Monitor's Overview rebuilt (the approved mockup resmon-1): Processor, Memory, Disk, Network and Graphics, each with its chips (use, speed, temperature, memory in use and in swap, memory pressure, the busiest drive, down / up, the graphics card) and its top programs with their PID; click a heading to fold it; tick programs to see only them in every section; the list scrolls instead of being cut off (needs testing on a device)
  • Resource Monitor's Memory tab (mockup resmon-3): the bar shows compressed memory too, and the numbers under it: what zram holds and its ratio, the drive swap, compressed memory's real size, committed; programs' Compressed column (needs testing on a device)
  • Resource Monitor's Processor tab: Priority for each program, and the selected program's open files (with their C:\ names) (needs testing on a device)
  • Resource Monitor's Network tab: listening ports with who can reach each (this PC only, Tailscale only, any network) and open connections, with the program when it's yours (needs testing on a device)
  • Optimize drives (Task Manager › Performance › Disk › Health & settings): each drive's kind, SSDs and NVMe drives TRIMmed weekly (never defragmented) with the last run shown, and Optimize now (needs testing on a device)
  • Optimize drives on hard drives: Optimize now checks a hard drive's ext4 for fragmentation (e4defrag -c) and defragments only above a score of 30; never Btrfs or NTFS (needs testing on a device)
  • Main drive almost full: a pop-up at 90% full or under 10 GB free (and again under 3 GB) says "If the drive Hearth OS starts from fills up, your PC might not start properly" with Free up space (Settings › Storage). Hearth's partition holds the system and your files together with nothing set aside, so a full one can stop the login screen and session from starting (as happened on Anatase, same layout): Hearth now keeps a 2 GB emergency reserve while there's plenty of room and frees it at start-up or from the pop-up when under 2 GB are left, and a system update stops before downloading when under 5 GB are free (needs testing on a device)
  • The same almost-full warning in Hearth Disks' Disk Management: a banner over the volume list, and any volume with 10% or less free shows its free space in gold (needs testing on a device)
  • One AI address (Settings › Home server › AI devices, off until you turn it on): apps that speak OpenAI's API use the home server's address (http://<server>:8189/v1) and each chat, voice or speech-to-text request goes on to the first free device in your order that has the model, skipping one that's playing, on battery or off; Tailscale only, with the share code if you set one (needs testing on a device)
  • Home server › Alerts & power: Night maintenance (off until you turn it on; once a night at 2:30, 3:30, 4:30 or 5:30, only when nobody uses the PC and it isn't busy: TRIM, system logs kept to 1 GB, Flatpak app updates, downloaded package files cleared; each step on its own, never anything that touches starting the PC; Last night says what it did) and Power history (off until you turn it on; processor and graphics card watts every 5 minutes, 30 days kept, the last 24 hours as a graph with the average and kWh a day) (needs testing on a device)

Installed systems update themselves; see updates.
