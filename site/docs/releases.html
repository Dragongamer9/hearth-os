Release notes

What changed in each version of Hearth OS, newest first, and what's planned next.

Hearth OS 1.6 · November 6, 2026 Latest

  • Desktop Mode: Super+Up / Super+Down work again (Up maximizes, or makes a snapped half a quarter and a quarter its half again; Down does the opposite, then restores a maximized window, then minimizes). labwc refused the old keys ("action 'If' cannot be a child action"); a test now catches that (needs testing on a device)
  • The installer test runs again: both jobs install Hearth OS on Debian (the one next to SteamOS still asked for the archived Anatase) and the boot check refreshes apt before getting qemu (it stopped with exit code 100); failures say why on the run page
  • Tiles and Start screen app menus: move tiles, by dragging with the mouse, or Y (or Move in a tile's menu), the D-pad and A to drop (B puts it back); saved for you only when you drop one somewhere new. The hints say what X and Y do (needs testing on a device)
  • Tiles app menu: its search field sits in the bar next to the flame, as in the mockup; what you type shows there (needs testing on a device)
  • The app menus' Updates tile shows Steam games with an update waiting (Hearth's games list now says so; other stores don't report it) (needs testing on a device)
  • Settings › Network & internet › Wi-Fi: the network you're on at the top (name, signal, band, address; Properties, Disconnect, Forget), and Add a hidden network (needs testing on a device)
  • Settings › Hearth Link › Your devices (and a card on Settings' Home): your other Hearth devices' online or last seen, Game Mode / Desktop Mode / Server mode, what's playing, battery, CPU / GPU use and temperature, memory, graphics memory, drives, version and uptime, with the last hour in small graphs, their shared folders, Wake it and Remote desktop. Only over Hearth Link between paired devices; "Let my other devices see this device's status" turns it off (needs testing on a device)
  • Hearth Files shows your devices' shared folders by itself: a "Your devices" section in the sidebar (and the Open / Save windows) with each paired Hearth device's shares, other computers sharing at home, and Tailscale devices that share; one click opens one (the home name at home, the Tailscale name away), signing in once with Remember in the system keyring; clear words for a wrong password, a share that's off, a device asleep (Wake it) or Tailscale signed out; "How to open from Windows or a phone"; a "Show other devices in Files" switch (needs testing on a device)
  • Settings: Sound, Notifications, Power & battery, Date & time, Mouse & touchpad, Printers, Apps, Default apps, Controller and Handheld in titled groups of cards with icons, as in the mockups (nothing they do changed) (needs testing on a device)
  • Server mode (docs/SERVER-MODE.md): a third mode next to Steam Game Mode and Desktop Mode, its own light session (a small labwc with one full-screen dashboard: status, Play, a tile per service, alerts), off until you turn it on in Settings › Home server › Server mode; your services keep running as their own services and the dashboard shows and controls them (needs testing on a device)
  • Server mode always ends in Game Mode when something's wrong: off or missing files, the dashboard not appearing within a minute, closing three times right away, or failing twice in 10 minutes (then paused until you open it); with it off, Game Mode and Desktop Mode start exactly as before (needs testing on a device)
  • Server mode's Play button and Guide: a 5-second countdown showing what pauses and what keeps working (A now, B cancel), then Steam Game Mode; leaving Game Mode comes back to Server mode with "Back in Server mode"; Desktop Mode from the dashboard's menu (needs testing on a device)
  • While you play, AI chat switches to the small model (qwen3:14b on the processor) so your other devices still get answers, and the big one loads again when you're back; ComfyUI finishes its picture and keeps its queue (Light mode's own settings; models are never deleted) (needs testing on a device)
  • Settings › System › Startup: start in Game Mode, Desktop Mode or Server mode, and with Server mode an optional schedule (weekdays and the weekend); no schedule unless you make one, and a change never closes a game or leaves Desktop Mode (needs testing on a device)
  • Server mode stays awake, with lower power limits when nothing's busy (power-saver, the graphics card's limit) and the screen dimming to a clock, then black (needs testing on a device)
  • Server mode's web page over Tailscale (port 8460, phone and laptop layouts): status, pause and restart services, switch modes, sleep or restart; PIN protected (only its hash kept), Tailscale and this PC only, every permission switchable; a switch from the web counts down 10 seconds on the home screen (needs testing on a device)
  • Home server › AI chat: an "Uncensored (18+)" group behind "Show 18+ models" (off by default, so a family PC never shows them): Qwen3 30B-A3B and 14B abliterated, Dolphin 3 and Rocinante 12B (Mistral Nemo, for roleplay and writing), each name checked; "Download any model by name" (Ollama names or hf.co GGUFs, validated); the abliterated 14B can be the small model while you play (needs testing on a device)
  • Home server › Shared folders: share a whole data drive (also from Drives & undo), your whole Home (read only, one confirmation; read & write a second) or the system drive (read only only, two confirmations, its secrets blocked), each on your home network and Tailscale by default with a "Whole drive" / "Home" / "System drive" badge; hidden files stay blocked everywhere (needs testing on a device)
  • A read-only summary for your other Hearth devices (/api/summary, hearth-server-mode summary) for Hearth Link and Quick Access (needs testing on a device; a Hearth Link page for it is next)
  • Discord replaces Hearth Friends (Matrix, archived with the owner's okay, docs/ARCHIVED.md): the bar's Friends button is now Discord; the first press asks which Discord you want (the official app, recommended; Discord in a web window, nothing to install; or Dorion, lighter but unofficial, with its risk said plainly) and installs only what you pick when you press Install (docs/DISCORD.md) (needs testing on a device)
  • Discord's small window by the bar, on whichever edge the bar is: Discord's own window, so you reply to friends there; pressing the button again hides it without quitting (notifications keep coming); its size is remembered; Open full Discord makes it a normal window (needs testing on a device)
  • Settings › Gaming › Discord: which Discord, "Playing <game>" on Discord with a one-step setup (paste the application ID) and an on/off switch, Let friends ask to join, and an invite link to paste in a chat (needs testing on a device)
  • Ask to join / Join from Discord: a friend joining opens the game's page on their Hearth (Play / Install), or Play together (Sunshine to Moonlight, over Tailscale or the local network) with a one-time PIN shown on both screens that expires in 10 minutes (needs testing on a device)
  • Steam Game Mode: Quick Access › Hearth Link › Discord (open Discord, the switches, the PIN, setup), and Discord's notifications as toasts (needs testing on a device)
  • Hearth Friends' Matrix service is no longer built, shipped or started; your old Matrix data and settings are left where they were, untouched (needs testing on a device)
  • Fix: GOG games (and other games Hearth starts with Proton, like Epic's) didn't show up in Steam Game Mode: they started, but Steam Game Mode only shows windows carrying the number Steam gave the shortcut, and umu labelled the game's windows with its own. Hearth now gives the game's windows the shortcut's number, so the game comes to the front; existing shortcuts are fixed by themselves at the next sync. A game Steam is set to run with a compatibility tool (Properties › Compatibility) can't start either: Hearth Sync's panel now names those games and says how to turn it off (your setting, left as it is). Every failed start says why in Hearth's log ("GOG Tomb Raider: launch failed because …") and Send logs shows Proton's output of the last starts and Debian Steam's own logs (needs testing on a device)

Installed systems update themselves; see updates.

Coming next

Planned, in no fixed order. Something missing? Ask for it.

  • A new Steam-style USB installer that only installs (the Recovery USB stays the place to repair and go back)
  • Hearth startup animations, picked in Steam's Startup Movie setting or in Hearth Sync
  • Boot splash presets, switched safely, with a plain text start as the fallback
  • A Hearth GRUB theme; the boot menu stays visible as it is today
  • Heroic Games Launcher preinstalled
  • An install helper for Epic's Linux launcher, once an official download is confirmed
  • An app-update signing key, to turn on fast app updates between system updates (docs/APP-UPDATES.md)
  • Hearth Mod Organizer: LOOT masterlist sorting; files for the game's own folder (script extender loaders, ENB: MO2's Root Builder); Nexus downloads straight into an instance, mod categories, notes and update checks; FOMOD scripts and BAIN wizards (docs/MODS.md)
  • Ember: app pop-up notifications in full Mantel on Windows (Windows only shares them with packaged apps)

Hearth OS 1.1 · November 2, 2026 18 changes
  • Install Package no longer sits on "Reading the package…" forever, and settings pages that run a helper no longer hang: Hearth 1.0's Quickshell refused how the helper's environment was set ("Cannot assign QJSValue to QVariantHash"), so the job never started. It's set the way Quickshell expects now (Install Package, Settings pages, sign-in options, Wi-Fi with a password), and a job that still can't start says so instead of waiting.
  • No black screen when Steam was never set up: Steam's own first-time "Steam installer" question opened in a window Steam Game Mode doesn't show, so a device that hadn't used Steam yet (an Intel laptop on 1.0) sat on a black screen. Hearth now starts Desktop Mode instead and says to open Steam there once and sign in; Game Mode works from then on.
  • Steadier game sound: the image now includes RealtimeKit, so PipeWire gets the sound priority it asks for (without it, busy games like Hogwarts Legacy made the sound choppy on the Nvidia PC), and games through Proton get a 1024-sample buffer floor; Send logs gains a Sound section (RealtimeKit, outputs, buffer sizes, sound messages).
  • Game Mode and Steam Game Mode start at a mode the screen really has: a chosen resolution or refresh rate the connected screen doesn't list (the Nvidia PC's 2560 × 1440 at 120 Hz on a TV that has it only at 60 Hz, which made gamescope abort) is skipped for that start with a notice and Try again, session.conf kept as it is; Steam Game Mode retries once at the screen's own mode instead of failing; the ROG Ally's built-in screen gets its real 48–120 Hz range for Steam when gamescope doesn't know the panel (ROG Xbox Ally); Send logs now shows each screen's EDID and its modes with refresh rates (it said "no EDID" for every screen).
  • Settings are always remembered and never change by themselves: every settings file is saved all at once with a backup copy, a damaged one comes back from that copy instead of resetting to the defaults, two programs saving at once both keep their change, and when Game Mode has to drop a screen mode that won't start it tells you and offers it again (docs/SETTINGS-PERSISTENCE.md; needs testing on a device)
  • Hearth's old Game Mode is hidden everywhere (it only runs first-time setup): its settings are now in Desktop Mode's Settings (new Remote play, Games & stores, Storage and Steam Game Mode pages; Go back a version in Updates; logs and backup in About) or in their own apps (docs/SETTINGS-MOVE.md) (needs testing on a device)

  • On-screen keyboard looks for Mantel: Steam-style (default, follows your accent and dark/light), Hearth warm, High contrast, Frosted and Pocket, next to the first four, picked in Settings › Keyboard.
  • Decky Loader built into the image (pinned v3.3.1, checksum-checked at build), started for Steam Game Mode by hearth-decky@<you>.service without a password; earlier downloaded installs move over by themselves.
  • New USB installer, install-only, in the Steam-style look: full screen and controller-first (touch, mouse and an on-screen keyboard too), Welcome and screen rotation, Wi-Fi (optional), choose the drive (hold A to erase), you, time zone, install, remove the USB, restart into Steam Game Mode; first-time setup is folded in, so the old Game Mode screens no longer run after installing (needs testing on a device)
